# 运行模型

所有机器共用同一套运行口径：谁声明什么、升级改哪些量、结算怎么算，都按下面八条走。
理解这八条就能自己算出任意配置下的耗电、耗时与产量。

## 八条设定

1. **消费端机器提供 FE/t 消耗**：每台机器自带一个基准功率 P，是它满速处理一份配方时每 tick 的耗电强度。

2. **消费端配方提供配方耗时**：配方 JSON 里的 `time` 决定这份配方要处理多久，不写时取默认值。配方不再声明耗电。

3. **生产端机器提供 FE/t 生产**：引擎自带一个额定产出功率 P，是它烧一份燃料时的输出强度。

4. **生产端配方提供持续时间与 FE/t 修正倍率**：燃料配方给出「这份燃料烧多久」和「相对引擎额定功率的倍率 m」，
   实际产出率 = `P × m`。燃料不声明绝对 FE/t。

5. **运行速度默认 1，且只能是自然数**：每 tick 推进 1 格进度，记作 N。
   N 可以变，但只能取 1、2、3……这样的整数——一张提速卡写「+2」，装上去 N 就是 3。
   它只管时间走多快——`运行耗时 = 配方刻度 ÷ N`——不改变每 tick 的耗电；
   每 tick 耗多少电由第 1 条的运行功率单独决定。

6. **运行耗时由「配方刻度 ÷ 速度」得出**（向上取整到整 tick）：
   * 配方刻度 = `配方耗时 × 耗时倍率 D`（没装工序精简时 D = 1，刻度就是配方耗时本身）
   * 消费端：`运行耗时 = ceil(配方耗时 × D ÷ N)`
   * 生产端：`运行耗时 = ceil(持续时间 ÷ N)`（引擎不读配方刻度，D 对它不生效）

7. **并行运行数影响五项**：FE/t 消耗与生产、整机吞吐、物品堆叠上限、流体容量、FE 容量。
   一个周期并行处理 B 份：FE/t、产出、容量都 ×B，每份的推进速度与耗时不变。
   熔炼机的三条流水线是结构并行，每条流水线各自有 B——两者相乘，整机一轮最多 3 × B 份。

8. **全局倍率**同时作用在四个地方：
   * 并行运行数 ×k
   * 运行速度 ×k（`N = (1 + Σ速度增量) × k`）
   * 运行耗时 ÷k
   * FE/t 消耗与生产 ×k

   由于并行运行数与速度都乘 k，整机 FE/t 实际是 k²，每份耗电仍不变。

## 结算公式

```
消费端
  运行速度     N = (1 + Σ速度增量) × k     自然数，基准 1
  耗时倍率     D = 1 + Σ(耗时系数 − 1)      基准 1.0，工序精简给 0.90 / 0.80 / 0.70
  配方刻度     = round(T × D)              进度条的总刻度
  运行功率     = P × Σpower × B            面板上直接可见的那个 FE/t
  运行耗时     = ceil(配方刻度 ÷ N) = ceil(T × D ÷ N)
  每份耗电     = 运行功率 × 运行耗时 ÷ B = P × T × D × Σpower ÷ N
  容量         = 基础容量 × B

生产端
  实际产出率   = P × m × Σpower × B
  每份燃料的能量 = P × m × T
  运行耗时     = ceil(T ÷ N)

并行运行数
  B = (1 + Σ并行增量) × k
```

其中 `Σpower` 是功率通道的线性汇总（`1 + Σ(系数 − 1)`），`Σ速度增量` 是提速卡给出的
整数之和，`Σ(耗时系数 − 1)` 是工序精简的耗时缩减之和，`Σ并行增量` 是并行运行卡的份数之和：
功率只影响 FE/t，速度只影响每 tick 推进几格，耗时倍率只影响配方本身多长，
并行运行数只影响一个周期做几份，四者互不推导。
`T` 是基准刻度：消费端为配方耗时，生产端为持续时间；`m` 是燃料的 FE/t 修正倍率，`k` 是全局倍率。

## 举个账

以一台基准 100 FE/t、配方 200 tick 的加工机为例：

| 配置 | 速度 N | 耗时倍率 D | 并行运行数 B | 运行耗时 | 每 tick 耗电 | 每份耗电 |
|---|---|---|---|---|---|---|
| 无升级 | 1 | 1.00 | 1 | 200 | 100 | 20000 |
| 全局倍率 ×2 | 2 | 1.00 | 2 | 100 | 400 | 20000 |
| 全局倍率 ×4 | 4 | 1.00 | 4 | 50 | 1600 | 20000 |
| 超频回路 III（+3） | 4 | 1.00 | 1 | 50 | 100 | 5000 |
| 工序精简 III（-30%） | 1 | 0.70 | 1 | 140 | 100 | 14000 |
| 超频 III + 工序精简 III | 4 | 0.70 | 1 | 35 | 100 | 3500 |
| 节能回路 III | 1 | 1.00 | 1 | 200 | 75 | 15000 |
| 并行处理 III | 1 | 1.00 | 4 | 200 | 400 | 20000 |

四条增益路线各管一维：超频回路只抬每 tick 推进的格数，工序精简只缩短配方刻度，
两者装的都是「时间」但作用点不同，装在一起各自生效、互不折算；
节能回路不提速，只降每 tick 耗电；并行处理核心只加并行运行数，每份成本不变、整机总量翻倍。
耗时向上取整，所以实测每份耗电会比表里的理论值高一点点。

## 关于进度条读数

进度条悬停显示的是配方刻度而不是百分比：`已推进刻度 / 配方刻度`（刻度已计入耗时倍率）。
进度每 tick 推进 N 格，读数也随之一次跳 N——N = 1 时才是一格一格走；
所以看到的是配方自身的刻度，而不是现实流逝的时间。引擎的燃料条同理，
显示 `已消耗 tick / 持续时间 tick`。

## 改燃料数据

引擎的燃料表是数据包配方 `kenergyengineering:engine_fuel`，默认写在
`data/kenergyengineering/recipe/engine_fuel/` 下。一条配方长这样：

```json
{
  "type": "kenergyengineering:engine_fuel",
  "ingredient": { "tag": "kenergyengineering:common_ingots" },
  "engines": ["metalizer"],
  "duration": 250,
  "rate_multiplier": 1.0
}
```

* `ingredient`：物品（`item`）或标签（`tag`）。
* `engines`：适用引擎，可填 `extractor` / `metalizer` / `biomass`；省略表示全部引擎。
* `duration`：持续时间（tick），即额定功率下这份燃料的燃烧时长。
* `rate_multiplier`：对引擎额定 FE/t 的修正倍率。

同名文件放进数据包即可覆盖；用 KubeJS 也能直接加：

```js
ServerEvents.recipes(event => {
  event.custom({
    type: 'kenergyengineering:engine_fuel',
    ingredient: 'minecraft:coal',
    engines: ['extractor'],
    duration: 1067,
    rate_multiplier: 1.0
  })
})
```

精确物品的条目优先于标签条目。数据包没有收录的物品，会回退到原版燃烧时间按
20 FE / 燃烧 tick 折算，用来兼容其他模组添加的可燃物。
