# 更新日志编辑规则

本规则管两份文件：

| 文件 | 职责 | CI |
|---|---|---|
| `CHANGELOG_UNRELEASED.md`（根目录） | **未发布的累计调整**：开发期唯一要动的文件，下一个版本的发布说明草稿 | 不读 |
| `CHANGELOG.md`（根目录） | **已发布内容的留档**：版本段由维护者粘进 GitHub Release 正文，再送到 Modrinth 与 CurseForge | 读（自动补录去重与兜底插入） |

本仓库的发版入口是 GitHub Release，不是直接推 tag。维护者把 `CHANGELOG.md` 的版本段粘进 Release 正文，
CI 再把该正文送到 Modrinth 与 CurseForge。`publish.yml` 里的 PR 标签 changelog 只是兜底：
`CHANGELOG.md` 已有该版本段时，自动补录会跳过。

## 一、结构

### 未发布文件

- 首行 `# 未发布改动`，随后一行说明它与 `CHANGELOG.md` 的关系。
- 唯一的段落标题是 `## [未发布]`，不带日期。小节只能用 `###`，名称与顺序同第二节。
- 本文件不被 CI 读取。格式瑕疵不影响本次发布，但它是发版文案的唯一来源；
  小节名与顺序仍要与留档文件一致，否则搬运时还得重新归类。

### 留档文件

- 首行 `# 更新日志`。
- 版本段一律 `## [<版本>] - <YYYY-MM-DD>`：版本号不带 `v` 前缀，日期是发布当天。
- **`## [` 是版本段边界**：一段发布说明从版本段标题的下一行开始，遇到下一个行首 `## [` 停止。
  正文里不许出现行首 `## [`，否则手工搬运或后续自动化都会截断。
- 版本段标题不进发布正文；Release 标题由维护者另写。
- 版本段的版本号要与 `gradle.properties` 的 `mod_version` 一致；tag 另写 `v<版本>-1.21`。
- CI 的自动补录只按 PR 标签生成说明，是兜底，不是发布正文的来源。
- 留档文件里不再出现 `## [未发布]`；待发内容住在上面的文件里。
- `CHANGELOG.md` 里保留 `<!-- CHANGELOG_INSERT -->` 标记；新版本段插在标记之后，标记始终位于所有版本段之上。自动补录也只在这个位置插入兜底说明，不要删。

### 发版时（按顺序做完四步）

1. 把 `CHANGELOG_UNRELEASED.md` 里 `## [未发布]` 那一整段（含小节与条目）搬到 `CHANGELOG.md` 的
   `<!-- CHANGELOG_INSERT -->` 之后，即所有已发布版本段之上，标题改成 `## [<版本>] - <YYYY-MM-DD>`。
   往留档文件里加段落只在这一步发生。
2. 把 `gradle.properties` 的 `mod_version` 改成同一个版本号。
3. 把 `CHANGELOG_UNRELEASED.md` 清回骨架：标题、说明、空的 `## [未发布]`。
4. 已发布的版本段此后不再增减条目。发现归档段落里的事实写错了，写进 `CHANGELOG_UNRELEASED.md` 的
   「更正」小节，不回头改历史。

## 二、小节：固定六个，顺序固定

| 序 | 小节 | 收什么 | 句首动词 |
|:--:|------|--------|----------|
| 1 | 新增 | 玩家此前拿不到的东西 | 新增 |
| 2 | 支持 | 接进了别的模组或格式 | 支持 |
| 3 | 改进 | 已有的东西变好 | 改进 |
| 4 | 修复 | 此前是错的 | 修复 |
| 5 | 调整与依赖 | 有意为之的改动与版本下限 | 调整 |
| 6 | 更正 | 这份文档历史段落里写错的描述 | 更正 |

- 没内容的小节整节不写。代码的错归「修复」，文档的错才归「更正」。
- 留档文件里已封版的段落是归档，不再增减条目：不补新条目、不删旧条目、不合并、不调整条目顺序，
  也不调整小节顺序、不改小节归属、不改版本标题的文字。只允许修正错别字、标点与格式瑕疵。
- 历史小节名（Added / Changed / Fixed / Removed）不再使用。变更按内容归「改进」或「调整与依赖」，
  移除归「调整与依赖」，文档与构建的改动并进相关条目或直接写进 `docs/`。

## 三、条目

- **一行一条**：`- ` 开头，不换行、不套子列表。
- **一句短话，只讲事实**：多数条目 30 字上下，最长不超过 135 字节（约 45 汉字；含英文、数字的按字节算）。
  不写「此前…现在…」的对照，不写成因，不写副作用，不写实现机制（挂哪条总线、注册了哪个接口）。
- **只写上一已发布版本玩家能遇到的事**：同一版开发过程中自己引入又自己修掉的问题不写——玩家从没碰到过。
  判据：这条描述的症状或行为，在上一已发布版本的代码里成立吗？不成立就别写。
  这条只查讲「变化」的修复/改进/调整；「新增」「支持」只要那东西上一版不存在就成立。
- **句首复用小节名当动词**：「新增…」「支持…」「改进…」「修复…」「调整…」。抹掉首词后句子应仍成立。
- **加粗只给被改动的对象**，一条一次，加粗名词短语而非语气词。
- 行为边界压成一句跟在同一条里（如某模组缺席时这一档不出现）——那是事实，不是叙述。
- 细节写进 `docs/ARCHITECTURE.md` 或代码注释，不在更新日志里展开。
- 标点用全角，引号用「」，代码与文件名用反引号；不写 emoji、表格、截图、链接。

## 四、依赖下限的写法

放在「调整与依赖」末尾，句式固定：

```
- 依赖 **NeoForge 21.1.243**
```

只列**本次发版变动的**硬线下限；没变的不重复列。软依赖的建议版本写进条目正文。

## 五、发版前自检

- [ ] `grep -c '^- ' CHANGELOG_UNRELEASED.md` 为 0：没漏搬的条目（骨架里只有标题、说明与空的 `## [未发布]`）
- [ ] `git diff CHANGELOG.md` 只多出一段（就是搬过来的那段），且 `git diff CHANGELOG_UNRELEASED.md` 只少掉条目
- [ ] `grep -n '^## \[' CHANGELOG.md`：行首 `## [` 只出现在版本段标题，且文件里没有 `## [未发布]`
- [ ] `grep -n '^## \[' CHANGELOG_UNRELEASED.md`：只有 `## [未发布]` 一行
- [ ] 小节名与顺序符合第二节；无空小节、无裸列表（只查本次要发的版本段）
- [ ] 每条目句首动词与小节一致；一行一条、只讲事实
- [ ] 每条都属上一已发布版本玩家能遇到的变化（本版开发中自引入又自修复的已剔除）
- [ ] 变动的硬线下限已写进「调整与依赖」
- [ ] Release 正文与 `CHANGELOG.md` 的版本段一致；CI 日志只用于确认兜底补录是「跳过」还是「插入」，不是正文来源

## 六、正反例

正：

```
- 新增**频道系统**
- 修复超过 **64 种原料**的配方被错误拦截，导致合成任务无法推进的问题
- 调整**管道连接模式**：源边仅显式 PULL 面主动抽取；旧档管道需用扳手重设
```

反：

```
- 修复**配置面板钮对齐**：此前内容钮坐标系原点误取纹理内图形原点（=叠加层纹理原点 + 纹理 5px 原生留白），
  留白被计两次，6 个面配置钮与 3 个类型钮整体右下偏 5px，改用叠加层纹理原点后与底图逐像素对齐。
```

反例一条里说了成因、症状、修法三件事，还有两个坐标系。玩家只需要知道「配置面板按钮错位，已修」：

```
- 修复**配置面板按钮**与底图钮槽整体偏移 5px 的问题
```

还有一类该剔除的条目：玩家从没见过的同一版内部改动。

```
- 改进**GUI 素材目录**：重命名为英文并清理旧版 legacy 文件
```

素材目录改名只影响开发，玩家看不到；这类改动写进 `docs/ARCHITECTURE.md` 或提交说明，不进更新日志。
